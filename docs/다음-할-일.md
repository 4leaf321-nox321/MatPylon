- [ ] 창을 닫고 트레이에서 살아 있는지, 재부팅 뒤 자동으로 뜨는지

## 3. 실파일을 보고 정할 것 (개발계획 §9)

파일럿에서 실제 파일이 나오면 이것을 본다. **지금은 모두 추측값이다.**

| 볼 것 | 어디서 | 정해지는 것 |
|---|---|---|
| 파일 크기 | 이력 탭 「크기」 | 100MB 넘는 게 있으면 청크 업로드(I) |
| 장비가 파일을 한 번에 쓰나, 임시 이름으로 썼다 바꾸나 | 폴더를 지켜보거나 이력의 `seen` 이 얼마나 오래 가는지 | 안정화 시간 기본값(E). 임시 이름이면 확장자 필터로 거른다 |
| 네트워크 드라이브인가 | 소스 경로가 `\\` 로 시작하는지 | 스캔 주기. 감시(chokidar)는 안 붙인다 |
| 파일명 | 폴더의 실제 이름 20개 | **파일명 규칙** — 아래 |
| 하루 생성 개수 | 이력 탭 | 전송 주기(H). 기본 1시간 |

### 파일명 규칙 — 자동 등록률을 결정한다

수집함에 `needs_specimen` 으로 쌓이면 사람이 매번 붙여야 한다. 자동으로 붙으려면
힌트(`material_code`·`lot`·`specimen`)가 MatNexus 의 재료 이름·시료 로트·시편 이름과
**정확히** 맞아야 한다(서버는 재료 이름·grade·별칭에 맞춘다).

- [ ] 「소스 → 파일명 규칙」 에서 「MatNexus 참조 → 불러오기」 로 재료(맞는 코드)·로트·시편 끝자리를 본다
- [ ] 폴더의 파일이 전부 한 재료·한 로트면 「이 폴더의 기본값」 에 고정하고 규칙은 시편만 뽑는다
- [ ] 미리보기의 「MatNexus 대조」 열이 ✔(자동 등록) 로 채워질 때까지 규칙을 다듬는다 — ✔ 이면 실제로 붙는다
- [ ] 안 맞는 것은 파일에 없는 정보다 — 그건 파일 메타(프로파일 `identity`)나 사람 몫
- 알아 둘 것: MatNexus 이름 규칙은 `재료__순번__방향_순번` 이라 **로트는 이름에 없다**(예: `SECC_MDOI_1.0__01` 의
  `01` 은 순번, 로트는 `L240612`). 로트 힌트는 시료의 로트 칸과 맞아야 한다
- [ ] 장비 SW 의 파일명 설정을 바꿀 수 있으면 그쪽이 더 싸다 (`재료_로트_시편.tra`)

## 6. 파일럿 전에 고친 것 (v0.1.8)

되짚어 보다 나온 것들. 특히 첫째는 **조용히 틀리는** 부류였다.

- **네트워크 드라이브가 끊기면 큐가 통째로 날아갔다.** 폴더를 못 읽으면 스캐너가 빈
  목록을 돌려주고, 사라짐 판정이 대기 중이던 파일을 전부 `gone` 으로 찍었다. 드라이브가
  돌아와도 파일 내용이 그대로면 다시 안 잡혀 **영영 안 갔다.** 이제 못 읽으면 사라짐
  판정을 건너뛰고 화면·트레이 알림에 띄우며, `gone` 이던 파일이 다시 보이면 되살린다
- 원장 정리가 앱 시작할 때만 돌았다 → 하루 한 번. 장비 PC 는 몇 달씩 안 끈다
- `npm run lint` 가 설정 없이 실패하고 있었다 → eslint 도입, CI 에 추가
- 화면 테스트 0건이었다 → `tests/renderer` 16건(대시보드·소스 편집기·마법사)
